4
Parsing into Sections
Markdown is split into sections by H1–H6 headings. Each section gets a heading_path — a hierarchical path like "Chapter > Section > Subsection".
click for details ▾
Parser
parsers/markdown.py → parse_markdown()
Regex on ^#{1-6}\s+, skips headings inside code blocks
Result
list[Section] — objects with fields:
heading_path heading_level content
5
Chunking
Sections are split into optimally sized chunks. Large sections are split, small ones are merged. Code blocks and tables are kept atomic (never split).
click for details ▾
Chunking parameters
max_tokens: 512
min_tokens: 50
overlap_paragraphs: 2
Token estimation: words × 1.3
Algorithm
1. Split text into atomic blocks (paragraphs, code, tables)
2. If section > max_tokens → _split_text()
3. If section < min_tokens → _merge_small_chunks()
4. Add overlap (2 trailing paragraphs from previous chunk)
Result
list[ChunkData]: heading_path, content, token_count, parent_content
File
ingestion/chunker.py chunk_sections()

7
Text Enrichment & Cleaning
Before embedding, text is cleaned of Markdown artifacts and enriched: heading_path, document type and entities are added as a contextual prefix.
click for details ▾
Cleaning (text_cleaner.py)
Removes: bold/italic markers, links (keeps text), images, HTML tags, inline code
Unicode normalization → NFKC
Enrichment (enrich_for_embedding)
Prefix: [heading_path]
+ [type: api_reference]
+ [entities: GET /api/v1/..., ONVIF, ...]
Limit: 500 tokens (truncated if exceeded)
8
Vectorization — Embedding (Gemini)
Enriched chunks are sent in batches to Gemini Embedding API. Each chunk becomes a numeric vector of dimension 1024. Vectors are L2-normalized.
click for details ▾
Model
gemini-embedding-2-preview
Dimensions: 1024
API parameters
task_type: RETRIEVAL_DOCUMENT (indexing)
task_type: RETRIEVAL_QUERY (search)
Batch: up to 100 texts per request
Post-processing
L2 normalization via numpy:
vector / ||vector||₂
Library
google-genai (google.genai.Client)
numpy — normalization
Retry: up to 5 attempts with exp. backoff
File
ingestion/embedder.py → embed_texts() embed_query()

Chunks, their metadata and embeddings are written to the chunks table. The vector is stored in a vector(1024) column. The document transitions to status ready.
