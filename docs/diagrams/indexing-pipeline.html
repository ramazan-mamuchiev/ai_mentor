4
Парсинг в секции (Sections)
Markdown разбивается на секции по заголовкам H1–H6. Каждая секция получает heading_path — иерархический путь вроде «Chapter > Section > Subsection».
нажмите для деталей ▾
Парсер
parsers/markdown.py → parse_markdown()
Regex по ^#{1-6}\s+, пропуск заголовков внутри code-блоков
Результат
list[Section] — объекты с полями:
heading_path heading_level content
5
Чанкинг (Chunking)
Секции разбиваются на чанки оптимального размера. Крупные секции дробятся, мелкие — объединяются. Код-блоки и таблицы сохраняются атомарно (никогда не разрезаются).
нажмите для деталей ▾
Параметры чанкинга
max_tokens: 512
min_tokens: 50
overlap_paragraphs: 2
Оценка токенов: words × 1.3
Алгоритм
1. Разбить текст на атомарные блоки (абзацы, код, таблицы)
2. Если секция > max_tokens → _split_text()
3. Если секция < min_tokens → _merge_small_chunks()
4. Добавить overlap (2 последних абзаца предыдущего чанка)
Результат
list[ChunkData]: heading_path, content, token_count, parent_content
Файл
ingestion/chunker.py chunk_sections()

7
Обогащение и очистка текста
Перед эмбеддингом текст проходит очистку от Markdown-артефактов и обогащается: добавляются heading_path, тип документа и сущности как контекстный префикс.
нажмите для деталей ▾
Очистка (text_cleaner.py)
Удаление: bold/italic маркеров, ссылок (оставляет текст), изображений, HTML-тегов, inline-кода
Unicode нормализация → NFKC
Обогащение (enrich_for_embedding)
Префикс: [heading_path]
+ [type: api_reference]
+ [entities: GET /api/v1/..., ONVIF, ...]
Лимит: 500 токенов (усечение при превышении)
8
Векторизация — Embedding (Gemini)
Обогащённые чанки отправляются батчами в Gemini Embedding API. Каждый чанк превращается в числовой вектор размерностью 1024. Векторы нормализуются по L2.
нажмите для деталей ▾
Модель
gemini-embedding-2-preview
Размерность: 1024
Параметры API
task_type: RETRIEVAL_DOCUMENT (индексация)
task_type: RETRIEVAL_QUERY (поиск)
Батч: до 100 текстов за запрос
Постобработка
L2-нормализация через numpy:
vector / ||vector||₂
Библиотека
google-genai (google.genai.Client)
numpy — нормализация
Retry: до 5 попыток с exp. backoff
Файл
ingestion/embedder.py → embed_texts() embed_query()
9
Сохранение в PostgreSQL + pgvector
Чанки, их метаданные и эмбеддинги записываются в таблицу chunks. Вектор хранится в колонке vector(1024). Документ переходит в статус ready.
нажмите для деталей ▾
Таблица chunks
id, document_id, chunk_index,
heading_path, heading_level,
content (оригинал), content_clean,
parent_content, token_count,
embedding vector(1024),
doc_type, entities (JSONB)
Индекс HNSW
HNSW + vector_cosine_ops
m = 16, ef_construction = 128
ef_search = 128 (на запрос)

Метрика: cosine similarity
1 - (a <=> b)
Библиотеки
SQLAlchemy (async) pgvector-python PostgreSQL 16
Обновление документа
status → ready, indexed_at → now()
total_chunks, total_tokens, embedding_model,
embedding_dims, timing метрики
Где используется Gemini
